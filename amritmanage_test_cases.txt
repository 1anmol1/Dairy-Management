PART 1: MULTI-TENANT INITIAL SETUP & SYSTEM SEEDING
================================================================================

TC-1.01: System Initialization Seeding
  - Pre-requisites: Fresh database (MongoDB empty/reset).
  - Action / Command line: 
    1. Open terminal in backend directory.
    2. Run: `npm run seed:superadmin`
  - Step-by-step Verification:
    1. Open your MongoDB GUI client (Compass/Atlas) or shell.
    2. Inspect the `users` collection.
    3. Verify that a user exists with role `superadmin`, email matching SUPER_ADMIN_EMAIL (or default 'superadmin@amrit.in'), and hashed password.
    4. Verify that the `systemconfigs` collection has a singleton document with `isInitialized: true` and `key: "system"`.
    5. Verify the `planconfigs` collection is seeded with 3 plans: "silver", "gold", "platinum" showing correct limits (e.g., maxCustomers, maxStaff).

TC-1.02: Localhost Setup Wizard Access
  - Action:
    1. Navigate to browser url: `http://localhost:5000/setup` (from localhost machine).
    2. Navigate to same url from a remote machine or using a mock non-localhost header (e.g., using Postman or mobile device).
  - Step-by-step Verification:
    1. On localhost: Setup Wizard page loads showing MongoDB and JWT Secret config form.
    2. On remote machine: Verify the app returns a `404 Not Found` (or redirection to 404 page) to prevent external access to configuration wizard.

  - Action:
    1. Log in as Staff Rajesh Pawar.
    2. Go to "Milk Collection Intake".
    3. Select Farmer = "Balu Haribhau".

  - Step-by-step Verification:
    1. SNF is auto-calculated dynamically as `8.26%` based on Richmond's Formula:
       `Calculated SNF = (CLR / 4) + (0.2 * FAT) + 0.36`
       `Calculation: (28 / 4) + (0.2 * 4.5) + 0.36 = 7.0 + 0.9 + 0.36 = 8.26%`
    2. Confirm SNF cannot be edited manually to prevent manual entry errors.
    3. Submit collection. Verify message: "Collection recorded successfully."
    4. Check Farmer balance: Balance should increase by `netAmount` calculated.

PART 9: SECURITY, COMPRESSION, AND RATE LIMITING AUDITS
================================================================================

TC-9.01: Morgan HTTP Request Logging
  - Action: Generate API requests to backend server.
  - Step-by-step Verification:
    1. Verify backend terminal console displays Apache-style output logs for each request:
       Format: `IP - - [date] "METHOD PATH HTTP/version" STATUS SIZE "REFERER" "USER-AGENT"`

TC-9.02: Gzip Compression
  - Action: Open Chrome DevTools -> Network -> Select large JS file (e.g. `main.js`).
  - Step-by-step Verification:
    1. Under Response Headers, verify: `Content-Encoding: gzip`.
    2. Verify total transfer size is compressed (typically 3x to 5x smaller than actual resource size).

TC-9.03: Helmet Security Headers Validation
  - Action: Fetch health check route using `curl -I http://localhost:5000/api/auth/me` or similar.
  - Step-by-step Verification:
    1. Verify response headers include:
       - `X-Frame-Options: DENY` (Blocks Clickjacking)
       - `X-Content-Type-Options: nosniff` (MIME sniffing block)
       - `Content-Security-Policy` (CSP parameters blocking unauthorized scripts)
    2. Verify `X-Powered-By` header is NOT present in headers list.

TC-9.04: MongoDB Injection Prevention (mongoSanitize)
  - Action: Send POST request to `/api/auth/login` with body payload containing mongo query selector:
    `{ "identifier": { "$gt": "" }, "password": "any" }`
  - Step-by-step Verification:
    1. The server sanitizes the input, stripping the `$gt` operator.
    2. Login fails with `401 Unauthorized` / "Invalid credentials." instead of logging into the first user in the database.

TC-9.05: API Rate Limiting (Too Many Requests check)
  - Action: Using a script or curl loop, send 101 requests within 1 minute to `/api/auth/login`.
  - Step-by-step Verification:
    1. The first 100 requests return standard response.
    2. The 101st request returns HTTP Status `429 Too Many Requests`.
    3. Response body displays: "Too many requests from this IP, please try again after 15 minutes."
